# 工作台改版设计方案

> 用 taste-skill（反模板味前端设计方法论）产出。日期：2026-09-03。
> 范围声明（诚实先行）：taste-skill 自身定位是 landing/portfolio，dashboard 属于其声明的「范围外」，正统工具是 Fluent/Carbon（React 系）。本项目为 Vue3 + Element Plus，换组件库不现实，因此本方案只取 taste-skill 的可迁移部分：Design Read、三拨盘、反默认纪律、色彩校准、改版协议（先审计后动手）、预检清单。组件基座维持 Element Plus，通过 token 覆盖层治理视觉。

---

## 1. Design Read（设计读判）

**把这个项目读作：面向开发者/管理者的 B2B 内部工具工作台改版（Redesign - Overhaul：换视觉语言，保留信息架构与内容），气质取「克制现代 SaaS」（Linear/Vercel 一族），载体为 Element Plus + CSS 自定义属性 token 层，不引入新依赖。**

三拨盘（dashboard 场景 override 掉 landing 基线）：

| 拨盘 | 值 | 理由 |
|---|---|---|
| DESIGN_VARIANCE | 3/10 | 工具界面要网格纪律和对齐感，不要艺术性错位 |
| MOTION_INTENSITY | 3/10 | 只保留 hover 反馈与状态过渡，纯 CSS，不加动画库 |
| VISUAL_DENSITY | 6/10 | 「日常应用」档：信息前置，砍掉大留白，现状最大的问题就是密度太低 |

## 2. 现状审计

**保留：**
- 信息架构（概览条 → 我的 Agent → 右栏辅助），导航结构、路由、组件 API 全部不动
- 品牌资产：Agent 头像图（真实图片，有辨识度）
- Element Plus 交互组件（表单/消息/开关），交互习惯不破坏

**废弃（土味清单）：**
- 默认 `#409EFF` 被当万能色：大数字、按钮、图标全部同蓝，无层次
- 1px 灰边框白卡片平铺，无阴影层次、无 hover 生命感
- 统计卡 4 个大数字占一整屏高度，信息密度极低
- `10000.0% 成功率` 直接露出（0 会话除法的脏数据 + 未格式化）
- emoji 与 Element 图标混用（👋 🏆 vs Tools/Coin）
- 快速操作 3 个白框按钮堆叠，像未完成的占位符
- 间距无系统：卡片间距、区块间距、行距各是一套
- 现有 `style.css` 全是硬编码色值（#333/#909399/#f5f7fa），无 token

## 3. 设计令牌（新增 `frontend/src/styles/tokens.css`）

```css
:root {
  /* ---- 表面与文字：冷灰一族，全站只此一族灰 ---- */
  --bg-page: #f6f7f9;          /* 页面底，比现在的 #f5f7fa 更中性 */
  --bg-surface: #ffffff;        /* 卡片面 */
  --bg-hover: #f2f3f5;          /* 行/卡片 hover 面 */
  --border-1: #e9eaec;          /* 主边框（hover 时可消失，用阴影接管） */
  --text-1: #18181b;            /* 标题/主文字，近黑非纯黑 */
  --text-2: #61646b;            /* 次要文字 */
  --text-3: #9b9ea6;            /* 辅助/占位 */

  /* ---- 强调色：唯一一个，克制使用 ---- */
  --accent: #3b5bdb;            /* 靛蓝，比 #409EFF 沉稳；只用于主按钮、链接、关键数字 */
  --accent-hover: #3350c4;
  --accent-soft: #eef1fb;       /* 强调色淡底（选中态/标签底） */

  /* ---- 状态色：只表达真实状态，不做装饰 ---- */
  --st-running: #2f9e6e;        /* 运行中/已发布 */
  --st-warning: #c47f17;        /* 调试中/警示 */
  --st-danger: #d64545;         /* 错误 */
  --st-idle: #8d919b;           /* 草稿/空闲 */

  /* ---- 形状锁：全站唯一圆角系统 ---- */
  --r-card: 12px;               /* 卡片/面板 */
  --r-control: 8px;             /* 按钮/输入框 */
  --r-pill: 999px;              /* 标签/状态点容器 */

  /* ---- 阴影：色相跟随背景，不用纯黑投影 ---- */
  --shadow-card: 0 1px 2px rgba(24, 24, 27, 0.04);
  --shadow-lift: 0 8px 24px rgba(24, 24, 27, 0.10);   /* 仅 hover 出现 */

  /* ---- 字体：中文优先系统栈 + 等宽数字 ---- */
  --font-ui: -apple-system, BlinkMacSystemFont, "PingFang SC",
             "HarmonyOS Sans SC", "Microsoft YaHei", "Segoe UI", sans-serif;
  --font-num: "JetBrains Mono", "SFMono-Regular", Consolas, monospace;
}
```

配套全局规则（追加进 `style.css`）：
- 所有统计数字：`font-family: var(--font-num); font-variant-numeric: tabular-nums;`
- Element Plus 主色改绑：`--el-color-primary: var(--accent)`，让 EP 组件自动跟随
- 间距系统：区块间 24px、卡片间 16px、卡内 16/20px，其余一律不允许自造
- 图标：只用 Element Plus Icons，UI chrome 内禁 emoji

## 4. 逐区块改造

### 4.1 页头
- 「👋 欢迎回来」→ 「欢迎回来，{username}」（去 emoji）；副标题从静态文案改为真实状态一句话：「N 个 Agent，M 个会话进行中」
- 高度压缩到 48px 行高级别，不再独占一块

### 4.2 概览条（替换 4 张统计卡）
4 张大卡合并为**一条概览卡**，内部 4 段用竖分隔线：

```
Agent 总数   已发布   进行中会话   今日 Token 消耗
   10         2         1            128.4k
```

- 标签 12px `--text-2`，数值 24px tabular
- 指标换成对管理者有信息量的：总数 / 已发布 / 进行中会话 / 今日 token（现状的「调试中/草稿」合并进 Agent 页筛选，不上首屏）
- 数值加载用 `el-skeleton`，禁止白屏后跳数

### 4.3 Agent 卡片（重点）
```
┌──────────────────────────────────┐
│ [头像] 前端工程师        [草稿]   │   ← 状态标签用语义色，草稿=灰、已发布=绿
│        专注前端                   │
│                                  │
│ 工具 9    会话 0    成功率 —      │   ← tabular 数字；0 会话时成功率显示 —
│                     进入会话 →    │   ← hover 才出现的主操作
└──────────────────────────────────┘
```
- 状态标签前置到标题行，一眼分出草稿/发布（现状「草稿」灰标签淹没在卡里）
- 统计行：`--text-2` 标签 + tabular 数值；分隔用间距，不用中点堆叠
- hover：`translateY(-2px)` + `--shadow-lift` + 「进入会话 →」浮现，150ms ease-out；`prefers-reduced-motion` 下退化为纯色变化
- 卡片点击进会话控制台；头像圆角统一 `--r-control`
- 空态：居中插画位 + 「还没有 Agent，创建第一个」按钮，不留白板

### 4.4 快速操作（撤卡）
- 撤掉整张「快速操作」卡：新建 Agent 上移为「我的 Agent」卡头右侧主按钮（原位置不变，只是合并进来）
- 「注册工具」「查看监控」降级为页头下的一行文字链接，或并入右栏
- 原则：卡片必须承载内容，不能只装按钮

### 4.5 最近任务
- 每行：Agent 头像（20px）+ 会话标题 + 状态标签 + 相对时间 + token 数（tabular）
- 行 hover `--bg-hover`，点击直达会话控制台
- 空态文案：「暂无会话记录」

## 5. 数据与文案修正（随改版一起修）

| 问题 | 修法 |
|---|---|
| `10000.0% 成功率` | 双重修复：(a) 计算处 0 会话返回 null；(b) 展示处 null/0 会话一律显示「—」，百分比统一保留 1 位且上限 100 |
| 数字未格式化 | `format.ts` 增加 `formatCompact`（128.4k）与 `formatPercent`（含 — 兜底） |
| 静态副标题 | 接真实统计接口，取不到就显示空态文案，不显示编造数字 |
| 文案语气 | 界面文案禁中点堆叠（a · b · c 最多 1 个/行）、禁 AI 腔形容词（无缝/赋能/极致），按钮 ≤ 4 字 |

## 6. 明确不做（本项目的 AI Tells 禁区）

- 紫色渐变、玻璃拟态、发光描边、深色网格 hero（AI 默认审美一律不进工具界面）
- 装饰性彩色圆点（状态点只允许出现在真实语义状态上，每区块至多 1 处）
- 渐变大数字、彩色描边卡、霓虹 hover
- 混用第二套图标库或继续 emoji 图标
- 每张卡都加循环微动画

## 7. 落地计划

| 阶段 | 内容 | 文件 |
|---|---|---|
| P1（本次） | tokens.css + style.css 接线 + EP 主色改绑 + DashboardView 重排 + 数字格式化 + 成功率 bug 修复 | `src/styles/tokens.css`、`src/style.css`、`src/views/dashboard/**`、`src/utils/format.ts`、对应后端/前端统计取数处 |
| P2 | token 铺到布局层（侧边栏/顶栏）与列表页 | `components/layout/**`、各列表页 |
| P3（可选） | 暗色模式：token 层已就绪，换一组变量值即可；默认跟随系统 | `tokens.css` 的 `prefers-color-scheme` 块 |

**决策点（默认按推荐执行，可否决）：**
1. 强调色：推荐靛蓝 `#3b5bdb`（替代 `#409EFF`）。备选：保持 EP 蓝但收权（只用于主按钮）。
2. 暗色模式：P1 不做但 token 化预留，P3 实现。

## 8. 验收预检（改版完成后逐项过）

- [ ] 全站只有一个强调色，且饱和度受控
- [ ] 一套圆角系统（卡 12 / 控件 8 / 药丸 999）无混用
- [ ] 所有统计数字 tabular 等宽，0 会话成功率显示 —
- [ ] 无 emoji 出现在 UI chrome；图标单一来源
- [ ] 每张卡有真实内容（无纯按钮卡）；空态/加载态/错误态齐全
- [ ] hover 有反馈，`prefers-reduced-motion` 下退化
- [ ] 文字对比度 WCAG AA（--text-2 on white = 5.9:1 ✓）
- [ ] 页面无横向滚动，1440/1280/1024 三档宽度检查
