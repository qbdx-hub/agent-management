# 移动端接入方案

> 现状：`myagent-ui/index.html` 是移动端 UI 设计资产代码化的**单文件原型**（原生 HTML/CSS/JS、零依赖、全 Mock、8 屏可交互）。
> 目标：把它接上 agent_management 后端，变成可真实使用的移动端 H5 应用。
> 接口逐屏明细见《[移动端接口文档](移动端接口文档.md)》。

---

## 1. 架构选型

### 1.1 结论

**新建独立工程 `frontend-mobile/`：Vite + Vue 3 + TypeScript + vue-router + Pinia + Axios，样式直接复用原型的 CSS 设计令牌与组件样式（不引入移动端组件库），SSE 沿用 XHR 流式方案，开发期 Vite proxy 转发 `/api/v1` 到 `:8080`。**

```
myagent-ui/index.html          ← 设计资产（保持原样，作为视觉对照）
agent_management/
├── backend/                   ← Spring Boot（新增 3 组最小接口，见接口文档 §10）
├── frontend/                  ← PC 管理端（Vue3 + Element Plus，不动）
└── frontend-mobile/           ← 移动端（本次新建）
    ├── src/
    │   ├── styles/tokens.css      ← 原型 :root 设计令牌 + 通用样式（.card/.tag/.hero-card…）
    │   ├── api/                   ← http.ts(Bearer/401拦截) + auth/agent/session/kb/cost/security
    │   ├── stores/                ← auth.ts(token+用户) / prefs.ts(用户偏好)
    │   ├── router/                ← /login + 4 个 Tab 页 + 子页
    │   ├── components/            ← AgentCard/StatusTag/Bubble/CodeBlock/Slider/Switch…
    │   └── views/                 ← home/ chat/ station(知识库)/ profile/ keys/ models/ notify/ help/
    └── vite.config.ts             ← proxy: /api/v1 → localhost:8080
```

### 1.2 为什么选它（备选对比）

| 方案 | 判断 |
|---|---|
| **B. Vite + Vue3 + TS，复用原型 CSS（✅ 选定）** | 与 PC 端完全同栈，`api/http/stores` 的写法、token 处理、XHR-SSE 方案直接平移；原型本身就是零依赖纯 CSS（TDesign Dark 令牌齐全），搬进组件即 100% 视觉还原，不引组件库就没有样式对齐成本 |
| A. 继续单文件 HTML 加 fetch | 无路由/构建/类型，8 屏 + 登录 + SSE + 分页塞一个文件不可维护，仅适合 demo |
| C. Vant / TDesign Mobile Vue 组件库 | 组件现成，但视觉与设计稿必然有差距，要大量覆盖样式；本项目页面少（9 屏），自绘更划算 |
| D. uni-app / Taro 跨端 | 目标是“个人使用不上线”，H5 已够；跨端框架构建链复杂、**小程序不支持 SSE**（对话核心功能要改成轮询），得不偿失 |

### 1.3 关键技术决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 流式对话 | XHR `onprogress` 解析 SSE（POST + Authorization 头） | `EventSource` 只支持 GET 且不能带请求头；PC 端 `api/session.ts` 已有成熟实现，直接移植 |
| 认证 | 复用 `POST /auth/login` 的 Bearer token；axios 拦截器统一注入，401 清 token 跳登录 | 后端零改动；`expiresAt` 到期前端主动登出 |
| 联调 | Vite `server.proxy` 把 `/api/v1` 转发到 `:8080` | 与 PC 端开发方式一致，无跨域问题 |
| 部署（个人使用） | `vite build` 产物由后端静态目录托管（Spring Boot `static/`），或本机任意静态服务器 | 不引入 nginx 等运维成本 |
| 首页数据 | 前端并行调 3 个现有接口聚合，不加后端聚合端点 | 请求数可接受，保持后端零侵入 |
| 深色模式 | 只有暗色（原型即 Dark 主题），开关项保留但不做空亮主题 | 个人使用，砍掉无效工作量 |

## 4. 风险与说明

1. **SSE 在移动端浏览器**：XHR 流式在 iOS/Android 现代浏览器均支持，但页面切后台会中断——回到前台重新拉 `GET /sessions/{id}` 回放并提示，不做后台续传。
2. **“云工作站”屏的业务错位**：原型按通用 AI 云平台设计（GPU 实例），本系统无此业务。已按路线 A 改造为知识库屏；若答辩需要原版视觉，再评估路线 B 的最小实现。
3. **原型的部分文案**（专业版/学生认证/GPU A100）属装饰性 Mock，接入时以真实数据为准，无对应字段的按接口文档映射规则处理。
4. **两个工程的关系**：`frontend-mobile` 独立于 `frontend`，不共享构建；仅复用类型定义与接口约定的“写法模式”（拷贝平移，不做 monorepo 抽包，避免工程复杂度）。
