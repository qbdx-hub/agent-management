# 移动端接口文档

> 对应 UI 原型：`myagent-ui/index.html`（8 屏，TDesign Dark，Mock 数据）。
> 本文档逐屏列出移动端需要的接口：**【现有】**可直接对接；**【新增】**为待实现的后端接口（附规格）。
> 配套方案见《[移动端接入方案](移动端接入方案.md)》。

---

## 0. 通用约定

| 项 | 约定 |
|---|---|
| Base URL | `http://<host>:8080/api/v1`（后端 context-path） |
| 响应包装 | `{ "code": 0, "message": "success", "data": … }`；`code = 0` 成功，非 0 见 `ResultCode`（如预算熔断 2301） |
| 认证 | 登录后持 `token`，请求头 `Authorization: Bearer <token>`；过期时间见登录响应 `expiresAt`（ISO 8601），过期返回 401，移动端应跳转登录页 |
| 分页 | 请求 `?page=1&pageSize=20`；响应 `data = { list: [...], total, page, pageSize }` |
| 时间 | ISO 8601 带时区字符串（`2026-09-02T10:30:00+08:00`） |
| SSE | 见 §3.3，移动端沿用 PC 端的 XHR 流式方案（`EventSource` 无法自定义 Authorization 头） |

## 1. 认证与账号

> 原型 8 屏中没有登录页，**需新增登录/注册页**，这是接入的第一个界面。

### 1.1 登录 【现有】
`POST /auth/login`

```json
// 请求
{ "username": "tongbei", "password": "******" }
// 响应 data
{
  "token": "eyJhbGciOi...",
  "expiresAt": "2026-09-03T10:30:00+08:00",
  "user": { "id": 1, "username": "tongbei", "nickname": "童倍", "avatar": "",
            "email": "", "role": "admin", "permissions": [],
            "workspaces": [{ "id": 1, "name": "默认工作空间" }] }
}
```

### 1.2 注册 【现有】
`POST /auth/register`，请求体 `{ username, password, nickname?, email? }`，成功 `data = null`。

### 1.3 当前用户 【现有】
`GET /auth/me` → `data = UserVO`（同上 `user` 结构）。移动端启动时调用，用于「我的」页与首页问候语。
原型的 `level: "专业版"` / `cert: "学生认证"` 无对应字段：`level` 映射 `role`（admin→专业版），`cert` 一期前端写死或不展示。

### 1.4 修改个人信息 【现有】
`PUT /auth/profile`，请求体 `{ username?, nickname?, email?, oldPassword?, newPassword? }`。

### 1.5 用户偏好读写 【新增】
支撑「06 模型偏好」「07 通知设置」两屏的持久化（当前后端只有 Agent 级配置，无用户级全局偏好）。

```
GET /auth/preferences
PUT /auth/preferences      // 全量提交
```

`data` 结构：

```json
{
  "defaultModel": "glm-5-turbo",
  "temperature": 0.7,
  "maxTokens": 4096,
  "replyStyle": "均衡",
  "notifications": {
    "agentFinished": true,
    "taskFailed": true,
    "instanceAlert": true,
    "tokenUsage80": false,
    "quietHours": { "enabled": true, "from": "23:00", "to": "08:00" },
    "channels": ["app", "email"]
  }
}
```

实现建议：`user` 表新增 `preferences` JSON 列（NULL 时返回上方默认值），后端不做字段级校验（个人使用）。

## 2. 屏 01 · 首页（工作台）

原型数据 → 接口映射，**不新增聚合端点**，前端并行发起 3 个请求：

| 原型元素 | 接口 | 字段映射 | 状态 |
|---|---|---|---|
| 用户问候（头像/昵称/等级） | `GET /auth/me` | `nickname`、`role` | 【现有】 |
| Agent 运行状态 · 运行中 N 个 | `GET /monitor/overview` | `activeAgentCount` | 【现有】 |
| 今日 Token 消耗 128.5k | `GET /monitor/overview` | `totalTokensToday` | 【现有】 |
| 本周完成任务 46 个 | `GET /monitor/token-trend` | 近 7 天 `callCount` 前端加总 | 【现有】 |
| 我的 Agent 列表 | `GET /agents?page=1&pageSize=5` | `name`、`modelName`、`status`、`updatedAt`（显示“更新于 xx”） | 【现有】 |

补充说明：
- `GET /agents` 支持 `keyword` / `status` / `tag` 过滤（`AgentQueryForm`）；`AgentSummaryVO` 含 `id/name/avatar/status/modelName/totalSessions/successRate/updatedAt`。
- 原型的 `lastActive: "活跃于 2 分钟前"`：Agent 表无此字段，一期用 `updatedAt` 近似；P2 可在会话结束时回写 `agent.last_active_at`。
- 快捷操作：`新建 Agent → POST /agents`（跳转创建页）；`上传文件 → §4.3 文档上传`；`终端 → GET /terminal/info` + `POST /terminal/exec`（2026-09-05 新增，沙箱内命令终端；owner/admin 直通，member 受空间成员终端开关（默认开放，PC 端空间设置可关），详见 §终端）。

### 2.1 监控总览 【现有】
`GET /monitor/overview`

```json
{ "activeAgentCount": 3, "runningTaskCount": 1, "todayCallCount": 46,
  "successRate": 98.2, "avgLatencyMs": 830, "p99LatencyMs": 2100,
  "totalTokensToday": 128500, "trends": { "callCountChange": 12.5, ... } }
```

### 2.2 Token 趋势 【现有】
`GET /monitor/token-trend?days=7` → `data = { summary: {...}, points: [{ date, tokens, callCount }, ...] }`（`TokenTrendPointVO`）。

## 3. 屏 02 · Agent 对话

移动端最核心的一屏，后端能力完整，**全部现有接口，零新增**。

### 3.1 会话列表/创建 【现有】

| 接口 | 说明 |
|---|---|
| `GET /agents/{agentId}/sessions?page=&pageSize=` | 会话分页列表，`SessionSummaryVO { sessionId, title, status, messageCount, totalTokens, totalCost, lastMessageAt, createdAt }`，`lastMessageAt` 可做“活跃于 xx 前” |
| `POST /agents/{agentId}/sessions` | 请求 `{ title?, variables?, executionMode? }` → `data = { sessionId }` |
| `GET /sessions/{sessionId}` | 会话详情 `SessionDetailVO { sessionId, title, status, messages: MessageVO[] }`，用于进入会话时回放历史 |
| `DELETE /sessions/{sessionId}` | 删除会话 |

### 3.2 发送消息（SSE 流式） 【现有】
`POST /sessions/{sessionId}/messages`，`Content-Type: text/event-stream`

请求体：`{ "content": "帮我写一个词法分析器", "mode": "auto" }`

事件流（仅这 4 种，与 PC 端一致）：

```
event: thinking   data: {"content":"正在思考..."}
event: content    data: {"content":"好的，这是一个"}     // 增量文本，逐段拼接
event: done       data: {"messageId":..., "tokenUsage":{"input":..,"output":..,"total":..,"cost":..}}
event: error      data: {"error":"..."}
```

移动端实现要点（与 PC 端 `api/session.ts` 相同的模式）：
- 用 XHR 发 POST + `onprogress` 解析流（**不能用 EventSource**：它只支持 GET 且无法带 Authorization 头）
- 收到 `content` 追加渲染，`done` 停止并展示 token 用量，`error` 展示错误并可重试
- 代码块高亮：原型已有 `codeblock` 样式，前端做轻量 markdown 解析即可

### 3.3 停止生成 【现有】
`POST /sessions/{sessionId}/stop` —— 中止后端执行并停止计费，前端同时 abort 本地 XHR。

### 3.4 顶部模型显示/切换 【现有】
显示：`GET /agents/{id}` → `AgentVO.aiModel`。
切换：`PUT /agents/{id}` 全量更新（模型字段 `aiModel`）——注意这是修改 Agent 配置，不是用户级偏好；用户级“默认模型”走 §1.5 preferences。

## 4. 屏 03 · 工作站

> **业务错位说明**：原型的“云工作站”（GPU 实例/CPU 内存存储指标）在本系统后端**没有对应业务**——系统是灵枢agent（Agent 管理平台），不存在算力实例。两个路线：
> **路线 A（推荐，P1）**：该屏改造为「知识库」屏——文件上传/检索是系统既有核心能力，移动端上传文件也与首页快捷操作呼应。
> **路线 B（P2 可选）**：为答辩演示补“最小 GPU 工作站”后端（接口规格见 §4.5），数据为演示性质。

### 4.1 知识库列表/CRUD 【现有】

| 接口 | 说明 |
|---|---|
| `GET /knowledge-bases?page=&pageSize=&keyword=` | 列表（返回 KnowledgeBase 实体：`id/name/description/docCount/status/createdAt`） |
| `POST /knowledge-bases` | `{ name, description? }` |
| `GET /knowledge-bases/{id}` / `PUT` / `DELETE` | 详情/改名/删除 |

### 4.2 文档列表/删除 【现有】

| 接口 | 说明 |
|---|---|
| `GET /knowledge-bases/{kbId}/documents?page=&pageSize=` | 文档列表（Document 实体：`id/name/fileType/fileSize/chunkCount/status/createdAt`，status: pending/processing/completed/failed） |
| `DELETE /knowledge-bases/{kbId}/documents/{docId}` | 删除文档 |

### 4.3 文档上传（直传 ≤50MB） 【现有】
`POST /knowledge-bases/{kbId}/documents`，`multipart/form-data`（字段 `file`），后端限制 50MB，与前端 `MAX_FILE_SIZE` 一致。上传后轮询文档 `status` 直到 `completed`（处理异步进行）。

### 4.4 知识检索 【现有】
`POST /knowledge-bases/{kbId}/search`，`{ "query": "...", "topK": 5 }` → 分块命中列表。对应原型的“搜索实例或文件”搜索框（语义改为“搜索文档与内容”）。

### 4.5 GPU 工作站（路线 B，P2 可选）【新增·待定】

```
GET /station/overview      → { gpuType, runningInstances, region,
                               metrics: [{ label: "CPU 利用率", value: 42 }, ...] }
GET /station/instances?keyword=  → [{ id, name, spec, region, status }]
```
需新建 `instance` 表 + 定时采集或随机指标（演示性质，不建议投入）。

## 6. 屏 05 · API 密钥管理 【新增】

> 后端未实现 API Key 管理（审计遗留项 11.7），移动端此屏需要以下 4 个接口。

| 接口 | 说明 |
|---|---|
| `GET /security/api-keys` | 当前用户的密钥列表 |
| `POST /security/api-keys` | 新建，**完整密钥仅创建时返回一次** |
| `PUT /security/api-keys/{id}/status` | 启用/停用 `{ "enabled": false }` |
| `DELETE /security/api-keys/{id}` | 删除 |

```json
// GET data（只给掩码）
{ "list": [{ "id": 1, "name": "生产环境密钥", "mask": "sk-my-****-****-8f2a",
             "status": "active", "createdAt": "2026-07-03T00:00:00+08:00",
             "lastUsedAt": null }], "total": 1 }
// POST 请求 { "name": "生产环境密钥" }
// POST data（明文仅此一次）
{ "id": 2, "key": "sk-my-9f2c81aa...", "mask": "sk-my-****-****-9f2c" }
```

实现约束：上限 5 个/用户（与原型一致）；存储只存 SHA-256 摘要 + 掩码，明文不落库；`SecurityController` 下新增路由。

## 8. 屏 07 · 通知设置

- 开关项读写：§1.5 preferences 的 `notifications` 对象。
- 「任务失败告警」对应后端既有告警体系：`GET /monitor/alerts/records`（告警记录列表）与 `GET/POST /monitor/alerts/rules`（告警规则）。一期移动端只做**偏好开关**；告警记录列表可作 P1 附加页。
- 免打扰时段、推送渠道为纯存储字段（`quietHours` / `channels`），一期不做真实推送拦截（个人使用无推送网关）。
