## 一、总体结论（一段话版）

这个系统**真实的部分**是：登录注册（BCrypt）、Agent/工具/工作流的增删改查、真实调用大模型对话（含真实 token 计费）、知识库上传与关键词/向量检索、审计日志、分页框架 —— 这条主干能跑通。
**假的部分**是：监控指标（成功率恒 100%、延迟恒 0）、告警系统（只读不写、永不触发）、预算控制（从不扣减）、工作流"运行"与人工审批（没有执行引擎，7 个相关实体是死代码）、工具连通性测试（接口不存在）、"流式"对话（一次性发完整段文本）、安全中心与工作空间管理（前端页面调用的是不存在的后端接口，整页假数据）。
**最危险的部分**是：多租户隔离可被一个请求头绕过、JWT 密钥硬编码在源码里、数据库密码/服务器公网 IP/真实姓名学号已被 git 跟踪且远程指向 GitHub。

## 二、急需处理（P0，本周内）

### 1. 任何人可以看到和操作任何租户的数据 🔴
- **大白话**：前端每次请求都带一个 `X-Workspace-Id` 请求头说明"我在哪个工作空间"，后端**直接相信这个头**，从不检查"你是不是这个空间的成员"。用任何账号登录后，把请求头里的数字改成 2，就能读写别的团队的工具、Agent、审计日志、成本数据。
- **叠加问题**：系统有 VIEWER/DEVELOPER/MANAGER/ADMIN 四级角色，但服务端**一条角色校验都没有**（全项目无 `@PreAuthorize`），注册即得的"观察者"能删除任何东西。
- **最彻底的一条**：删除告警规则的两个接口连工作空间都不校验，纯按 id 删（`MonitorServiceImpl.java:376-386`）。
- 证据：`SecurityUtils.java:41-57`、`SecurityConfig.java:57-61`；README 里写的 `WorkspaceInterceptor.java`（工作空间隔离拦截器）**这个文件根本不存在**。

### 2. JWT 密钥硬编码，可伪造任意用户身份 🔴
- 签发登录令牌的密钥在代码和配置文件里各埋了一个默认值（`JwtProperties.java:16`、`application.yml:87`）。环境变量没设就用公开密钥 → 任何人可离线伪造"我是 admin"的 token，且 24 小时内无法吊销（封号、改密码都无效）。

### 3. 敏感信息已经进了 git，远程指向 GitHub 🔴
已被 `git ls-files` 确认跟踪的文件：
- `backend/src/main/resources/application.yml` —— 数据库账密 `dev/dev123456@10.7.17.154`、Druid 控制台 `admin/admin123`、JWT 兜底密钥
- `frontend/.env.production` —— 公网服务器 IP `47.94.144.140`
- 5 份个人材料 —— 4 名成员**真实姓名+学号**、教师、学校班级
- `backend/uploads/` 下 3 个用户上传文件；`docs/wechat-chat-emotional.md`（与本系统无关的情感聊天语料残留，放错目录）
- 另：`backend.log` 里已实际打印出用户密码哈希和邮箱（MyBatis SQL 全量日志开着）
- ⚠️ 本机连不上 GitHub，无法确认是否已 push。**只要 push 过一次，以上全部公开。**

### 4. SSRF：可借服务器探测内网 🟠
Agent 的 `aiBaseUrl` 用户随便填（包括 `http://10.x.x.x` 内网地址），服务器会照着发请求，出错时还把内网响应内容回显给前端（`AiServiceImpl.java:42-58`、`SessionController.java:243`）。

### 5. 前端两处存储型 XSS 🟠
`SessionConsole.vue:148` 和 `KnowledgeDetail.vue:187`：把 AI 输出/文档内容**不做任何转义**就 `v-html` 渲染。AI 回复里带 `<img onerror=...>` 就会执行恶意脚本 —— 而 token 就存在 localStorage，可直接被偷。

### 三个让知识库"静默失效"的高危 Bug
1. **PDF 支持是假的**：白名单允许 pdf，但项目没有任何 PDF 解析库，直接把二进制按 UTF-8 解码 → 乱码切块、检索必错（`DocumentProcessingServiceImpl.java:80`）
2. **文档永不向量化**：`List<Integer>.contains(Long)` 装箱恒 false（同类坑修了 2 处，唯独这里漏了）→ 所有文档只存文本，状态却标 `completed`（`DocumentProcessingServiceImpl.java:260`）
3. **`@Async` 失效**：全工程无 `@EnableAsync`，文档处理实际同步阻塞请求线程，大文档必超时（`DocumentProcessingServiceImpl.java:60`）

### 其他 P1
- 前端"安全中心/工作空间管理"整模块调用不存在的后端（404），成员邀请、保存设置全是**假成功提示**；知识库**大文件分片上传**调用的 3 个接口后端不存在（>5MB 必失败）
- 数据库建表脚本与代码脱节：**缺 `document_chunk` 整张表**（RAG 核心）、`agent` 表缺 6 列（AI 配置+价格）、`budget` 缺 `created_by` —— 按文档建库直接跑不起来
- Druid 监控页 Security 放行 + 弱口令 + 无 IP 白名单；停用账号/改密后旧 token 仍有效；API Key 明文存库且脱敏函数对短 key 返回明文
- 审计日志操作人取自客户端可伪造的 `X-User-Name` 头
- 4 处 `pageSize: 100/200` 一次拉全量，分页形同虚设；SSE 组件卸载不关闭（整个前端无一个 `onUnmounted`）
